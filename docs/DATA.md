## Размер выборки

| | Train query | Test query |
|:--|--:|--:|
| Боксы целевых классов | 198 | 362 |
| Кадры | 35 | 86 |
| Дни | 25–26.10.2026 | 27–28.10.2026 |
| person | 84 | 153 |
| nude_hands | 63 | 131 |
| cup | 33 | 54 |
| tray | 18 | 24 |

В исходной train-таблице 670 строк; 472 `table` исключены из целевой задачи. Среди 198 оставшихся query — 109 ошибочных и 89 корректных. `nude_hand` нормализуется в `nude_hands`.

Координаты query приводятся к **1280 × 720**. Часть изображений сохранена как 640 × 360, поэтому код явно учитывает масштаб. Несогласованный масштаб координат и RGB — самостоятельный источник ложных ошибок.

## Что означает error

Бокс сопоставляется с GT того же класса. Порог IoU — 0.60. Используется взаимно-однозначное сопоставление: сначала максимум числа совпадений, затем максимум суммарного IoU. Поэтому дубликат может быть ошибкой, даже если геометрически близок к объекту.

Score модели ранжирует query по `error`; он не является confidence наличия объекта. Для подачи нужен CSV из двух столбцов:

```csv
id,score
01be9d3acfb01856,0.949170922067
```

Порядок и набор `id` сверяются с сохранёнными оригинальными сабмитами.

## Данные для replay

В `solutions/v52/inputs/` сохранены таблицы query без целевой метки, базовые скоры, frozen-эмбеддинги и прототипы. В `solutions/v58/replay_inputs.npz` — необходимые экспертные прогнозы и ожидаемый итог для проверки.

Train-метки в `reports/` используются только для аудита и оценки. Быстрый replay не обучает модель и не извлекает новую информацию из этих меток. Исторические скрипты обучения, в отличие от replay, ожидаемо используют train-labels.

Визуальные замечания к 43 test-боксам сохранены как отдельные гипотезы. Они не заменяют GT и не подавались в выбор финальной формулы V58.
